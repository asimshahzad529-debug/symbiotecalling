01

Getting started

Symbiote Calling runs voice calls through Google's Gemini Live — you bring your own API key, and the app does the rest. Your key is your login: the whole app stays behind the key screen until a key is entered.

Walkthrough: your first call
0%
  1. Open Settings — use the Settings tab in the top bar.
  2. Enter one Gemini API key. It powers every agent. Need one? Get a free key at aistudio.google.com/apikey.
  3. Open the Agents tab and pick anyone — try SymAgent, the featured card at the top.
  4. Tap Call and start talking. Say khuda hafiz or cut the call when you're done.
Key login · design mock

Design mock — the real key screen may differ.

Your key is never stored. It lives in server memory for the call only — never written to disk, never logged, never put in a URL. The Settings page shows only a status line, never the key itself.

Key profiles

Juggling more than one key — say a personal key and a demo key? Save named key profiles and switch from the key screen. Each profile keeps its own calls, memories, and custom agents, because everything is tied to the key's hash, never the key itself.

Appearance

  • Theme — light by default; one-tap dark mode via the sun/moon button in the top bar (remembered across visits).
  • Accent color — pick an accent in Settings and the whole app follows it. Press Ctrl+K anywhere and choose Toggle theme for a faster flip.

02

Agents

One hundred niche calling agents — a restaurant host, visa guide, interview coach, pharmacy assistant, chess coach, and 95 more — each with a fictional number from +1 (555) 010-0001 to +1 (555) 010-0100 that works only inside this app. Every agent has a gender-matched voice and its own AI portrait.

Hard limits on sensitive roles. Some agents carry baked-in guardrails: the salon booker never diagnoses, the legal assistant is not a lawyer, the pharmacy assistant gives general info only and refers to professionals. These are demos, not professional services.

SymAgent — the 101st agent

Sitting in the featured hero card above the directory is SymAgent (+1 (555) 010-0101) — the official AI representative of Symbiote Systems, the agency behind this platform. It knows the company's services (AI calling/voice agents, websites, AI chatbots, automation on Make/n8n), the portfolio, the socials, and the contact details — and it knows all 100 agents by name, niche, and number, because that directory is generated straight from the app's own code so it can never drift.

SymAgent won't talk pricing — it informs, impresses, and captures leads. If a caller is interested, it collects name, email, phone, and the service they want, and saves it as a note for the team to follow up.

Call transfer (SymAgent only)

Walkthrough: transfer to a specialist
0%
  1. Call SymAgent from the featured hero card.
  2. Ask about a specialist service — e.g. "I need someone who can help with my visa paperwork."
  3. Accept the offer to connect — SymAgent transfers you mid-call into a call with that specialist. Works with built-in and custom agents alike.

Clickable link chips

Ask SymAgent for socials, portfolio, or contact details and it drops clickable link chips into the in-call chat — Instagram, Threads, X, LinkedIn, Pinterest, Gumroad, the portfolio sites, client work (Aquifer Reach LLC), email, and WhatsApp. The URLs are server-side constants, so the model can never invent or inject its own links.

03

Custom agents

The Custom Agents page is where you build your own. Your custom agents live side-by-side with the built-ins — they're part of Symbiote Calling too, SymAgent knows about them, and it can transfer callers to them. Unlimited agents per key.

Walkthrough: build your first agent
0%
  1. Name — required. Make it memorable; callers hear it first.
  2. Number — required. Any random number works, it just has to be unique.
  3. Role — required. Pick a niche or write your own custom role.
  4. Tone — pick a preset (professional, friendly, …) to shape how the agent speaks.
  5. Voice — the voice picker lets you audition and assign a voice.
  6. Prompt — optional custom instructions; start from a prompt template if you like.
  7. Review & Create — your agent appears in the Agents list immediately, no reload needed.

Clone an agent

Found a built-in you like? Clone it to get a custom copy with the same voice and role, then tweak the name, prompt, or tone to make it yours. Custom agents themselves are never cloneable — only the 101 built-ins.

Saved per key. Custom agents are stored under your API-key profile — the same key always reloads the same agents, and a different key never sees them.

API v8

A small read-mostly JSON API powers the app — handy for dashboards, the embed widget, and your own integrations. All calls are same-origin; key-scoped routes identify the caller by the key's hash.

MethodEndpointReturns
GET/api/healthService status + agent count
GET/api/agentsAll 101 built-in agents (id, name, niche, number, voice)
GET/api/statsDashboard stats for the current key
GET/api/historyCall history for the current key
GET/api/memoriesSaved memories / call summaries
GET/api/v7/custom-agentsYour custom agents (send x-key-hash header or ?keyHash=)
Key scoping. History, memories, and custom agents are tied to the API key's hash — the key itself is never sent. Send the hash in the x-key-hash header (or ?keyHash=) exactly as the app does; a different hash sees a different dataset.
Voice calls are not REST. Calls ride a persistent WebSocket (/live) from browser → server → Google. The table above covers data endpoints only.

FAQ

Is this a real phone network? Can I call real numbers?

No. The +1 (555) numbers are fictional and work only inside the app — including your business line. This is a demo, not a phone company, emergency service, or medical/legal/financial provider.

Where does my API key go?

Into server memory for the call only. Never stored, never logged, never in a URL. Data is keyed to your key by hash, so only you see your history.

Can I use it without a microphone?

Yes — chat mode. Type your messages; the agent still answers by voice.

Are my calls recorded?

On your device, for you. Recordings and transcripts never leave your device — they only ever land in your own memory page and backups, which are yours.

Can I make my own agents?

Yes — the Custom Agents page (name, number, role, tone, voice, prompt), unlimited, saved per key. SymAgent even knows about them and can transfer callers to them.

Does my data survive redeploys?

Yes, if you did the DATA_DIR=/data volume step (see Memory & persistence). Otherwise redeploys wipe it — keep a JSON backup from the Memory page.

Why does SymAgent ask for my details instead of answering?

That's its job: it's the company rep. It informs and captures leads (name, email, phone, service) for the team to follow up.

Why won't it discuss pricing?

By design — SymAgent doesn't talk pricing. It connects interested callers with the team instead.

Memory & persistence

How memory works

Agents remember you. Every call saves notes, appointments, and the full transcript behind the scenes — plus an AI-written summary. The Memory page shows that summary per call; open any entry to read it, or download the transcript or the device recording from the same view.

When you call the same agent again, its recent memories are injected into its prompt — so it picks up where you left off.

Your data belongs to your key

Memories and history are tied to your API key by hash — the key itself is never stored, only a fingerprint of it. Change the key and everything resets cleanly, so keys never cross-contaminate.

Walkthrough: keep data across redeploys (Railway)
0%
  1. Railway dashboard → your service → Volumes → Add volume, mount path /data.
  2. Same service → Variables → add DATA_DIR=/data.
  3. Redeploy. History and memories now survive updates.
Tip: before any big change, go to Memory → Download backup (JSON) for a local copy. Restore puts it back. Until you do the volume step, a redeploy wipes everything — that will look like a bug if you forget.

The app also runs auto-cleanup in the background so old data doesn't pile up forever, and an audit log records important data events for your own peace of mind.

Deploying on Railway

Walkthrough: deploy
0%
  1. Push the repo to GitHub (npm test first — the suite runs with zero dependencies).
  2. Create a Railway project from that repo — it deploys the Node server automatically.
  3. Auto-deploy is on: every push to the connected branch redeploys, no manual step needed.
  4. Set env vars in the service's Variables:
    • DATA_DIR=/data — with a volume mounted at /data (see Memory & persistence).
    • GEMINI_API_KEY — optional server fallback; in practice each user enters their own key, so this can stay empty.
Why not serverless? A voice call needs one permanent open line held the whole time (browser → server → Google, via WebSocket). Serverless functions wake, answer once, and sleep — they can't hold that line. That's why the app runs as one always-on service.

Troubleshooting

No greeting yet — the agent stays silent?

The app sends a greeting trigger on connect, nudges the model once if it stays silent, and holds your mic closed until the greeting audio lands so you don't talk over it. The call screen shows "Connecting…" until that audio arrives. If the agent still doesn't greet first, say something or type in chat — it will respond. If it happens on every call with every agent, report it: it's the behavior we tune hardest.

Mic blocked or missing

Check Settings → mic default, and your browser's site permissions. Either way, calls fall back to chat mode automatically — you type, the agent answers by voice.

Key issues

  • "No key entered" — the app can't start a call without a key; paste one in Settings.
  • "Key changed" — memories and history are key-scoped, so switching keys shows a fresh slate. Your old data is untouched, tied to the old key.
  • Quota errors — the key's Gemini quota is exhausted; wait for it to reset or switch key profile.

Other hiccups

  • Choppy audio — on a hosted tunnel the voice path can degrade; on the deployed server it should be clean. Check your connection first.
  • "Search unavailable" — the agent's web search runs a 4-provider chain (DuckDuckGo instant → Wikipedia → Google News → DDG lite). If all four are blocked, it says so rather than inventing answers. Try again later.
  • Recording missing/empty — the mic was likely denied; allow it and call again.
  • Double greeting after transfer — report it; transfers should hand you over with a single greeting.
