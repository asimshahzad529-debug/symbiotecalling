Getting started

Symbiote Calling runs voice calls through Google's Gemini Live — you bring your own API key, and the app does the rest.

  1. Open the app and head to Settings.
  2. Paste one Gemini API key (get a free one from aistudio.google.com/apikey) — it powers every agent.
  3. Your key is your login: the app stays behind the key screen until a key is entered, and your data belongs to your key (see Memory & persistence).
  4. Go to Agents and tap Call on anyone.
Your key is never stored. It lives in server memory for the call only — never written to disk, never logged, never put in a URL. The Settings page shows only a status line like "Key set for this page session".

Key profiles

If you juggle more than one key (say, a personal key and a demo key), you can save named key profiles and switch between them from the key screen — each profile keeps its own calls, memories, and custom agents.

Other settings worth knowing

  • Model — you can change the Live model order yourself (default: gemini-3.8-live, with cheaper/fallback models after it).
  • Mic default — mic permission is requested only when a call starts; you can toggle the default here.
  • Theme — light by default, one-tap dark mode (remembered).
  • Accent color — pick an accent color and the whole app follows it.
02

Making calls

The agent directory

The Agents tab lists all built-in agents with their portrait, niche, and number. Use the search/filter box to find one by name or niche (try "visa" or "tutor"), or tap an agent card to open its profile sheet with details. Tap Call to start talking.

The dialer

Know the number? Open the Dialer and punch it in — smart dialer shows matching agents above the pad as you type, with exact matches highlighted. The dialer also has a recents tab so you can redial people you called before in one tap. Dialing an unknown number simply tells you it doesn't exist — nothing breaks.

The call screen

A Samsung-style phone slides up: Dialing… → Connecting… → a live timer in mm:ss. While the call is live you have:

  • Mute — silence your mic.
  • Keypad — a DTMF pad with real touch tones (handy for menus; tones never reach the model).
  • Chat — type and the agent answers by voice; has a close button.
  • Hang up — ends the call.
  • Floating bubble — shrink the phone into a floating bubble that stays on screen so you can browse agents while you talk.

You can also end calls hands-free: say "cut the call", "khuda hafiz", or just goodbye — the agent says farewell and hangs up itself.

No mic? No problem. If the microphone is blocked or missing, the call continues in chat mode — you type, the agent still answers by voice.
03

Agents

The 100 built-ins

One hundred niche calling agents — a restaurant host, visa guide, interview coach, pharmacy assistant, chess coach, and 95 more — each with a fictional number from +1 (555) 010-0001 to +1 (555) 010-0100 that works only inside this app. Every agent has a gender-matched voice and its own AI portrait.

Hard limits on sensitive roles. Some agents carry baked-in guardrails: the salon booker never diagnoses, the legal assistant is not a lawyer, the pharmacy assistant gives general info only and refers to professionals. These are demos, not professional services.

SymAgent — the 101st agent

Sitting in the featured hero card above the directory is SymAgent (+1 (555) 010-0101) — the official AI representative of Symbiote Systems, the agency behind this platform. It knows the company's services (AI calling/voice agents, websites, AI chatbots, automation on Make/n8n), the portfolio, the socials, and the contact details — and it knows all 100 agents by name, niche, and number, because that directory is generated straight from the app's own code so it can never drift.

SymAgent won't talk pricing and won't book appointments — it informs, impresses, and captures leads. If a caller is interested, it collects name, email, phone, and the service they want, and saves it as a note for the team to follow up.

Clickable link chips

Ask SymAgent for socials, portfolio, or contact details and it drops clickable link chips into the in-call chat — Instagram, Threads, X, LinkedIn, Pinterest, Gumroad, the portfolio sites, client work (Aquifer Reach LLC), email, and WhatsApp. The URLs are server-side constants, so the model can never invent or inject its own links.

Call transfer (SymAgent only)

Talking to SymAgent about a specialist service? It offers to connect you. Say yes and it transfers you mid-call into a call with that specialist agent. Transfer works with built-in agents and your custom agents alike.

04

Custom agents

The Custom Agents page is where you build your own. Your custom agents live side-by-side with the built-ins — they're part of Symbiote Calling too, SymAgent knows about them, and it can transfer callers to them.

The builder

  • Name — required.
  • Number — required; any random number works, it just has to be unique.
  • Role — required; pick a niche or write your own custom role.
  • Tone — pick from a few presets (e.g. professional, friendly) to shape how the agent speaks.
  • Voice — the voice picker lets you audition and assign a voice.
  • Prompt — optional custom instructions; start from a prompt template if you like.
  • Profile picture — optional; use the avatar cropper to frame it, or leave it blank for the default caller avatar.

There is no limit on how many you create. Custom agents are saved under your API-key profile, so the same key always reloads the same agents — and a different key never sees them.

Clone an agent

Found a built-in you like? Clone it to get a custom copy with the same voice and role, then tweak the name, prompt, or tone to make it yours.

05

During & after calls

While you're talking

  • In-call notes — jot down notes during the call; they're saved with that call's record.
  • Recording — every call is recorded on your device (a red dot shows it's rolling). Recordings never leave your device.
  • Chat & keypad — covered in Making calls.

After you hang up

Open the call in History (agent, number, time, duration) — its detail view holds everything the call produced:

  • Auto summary — a short AI summary (a few lines + the outcome) is generated after each call, free and in the background, never blocking anything.
  • Recording download / delete — play it back, keep it, or delete it.
  • Transcript download & search — download the full transcript or search inside it.
  • Call back — one tap calls the agent again.

History also has filters so you can narrow calls by agent or date range, and the dashboard shows your recent calls at a glance.

06

Memory & persistence

How memory works

Agents remember you. Every call automatically saves two things to the Memory page:

  • Notes — appointments, facts, and lead details the agent records during the call.
  • The full transcript — everything said on both sides.

When you call the same agent again, its recent memories are injected into its prompt — so it picks up where you left off. Open any memory for the full detail view.

Your data belongs to your key

Memories and history are tied to your API key by hash — the key itself is never stored, only a fingerprint of it. Change the key and everything resets cleanly, so keys never cross-contaminate.

Keeping data across redeploys (Railway)

On Railway the filesystem is wiped on every redeploy, so point the app at a persistent volume:

  1. Railway dashboard → your service → Volumes → Add volume, mount path /data.
  2. Same service → Variables → add DATA_DIR=/data.
  3. Redeploy. History and memories now survive updates.
Tip: before any big change, go to Memory → Download backup (JSON) for a local copy. Restore puts it back. Until you do the volume step, a redeploy wipes everything — that will look like a bug if you forget.

The app also runs auto-cleanup in the background so old data doesn't pile up forever, and an audit log records key data events for your own peace of mind.

Deploying on Railway

  1. Push the repo to GitHub (npm test first — the suite runs with zero dependencies).
  2. Create a Railway project from that repo — it deploys the Node server automatically.
  3. Auto-deploy is on: every push to the connected branch redeploys, no manual step needed.
  4. Set env vars in the service's Variables:
    • DATA_DIR=/data — with a volume mounted at /data (see Memory & persistence).
    • GEMINI_API_KEY — optional. If set, the server has a fallback key; in practice each user enters their own key in the app, so this can stay empty.
Why not serverless? A voice call needs one permanent open line held the whole time (browser → server → Google, via WebSocket). Serverless functions wake, answer once, and sleep — they can't hold that line. That's why the app runs as one always-on service.

Troubleshooting

No greeting yet — the agent stays silent?

Honest answer: greeting behavior is under active improvement. The app sends a greeting trigger on connect, nudges the model once if it stays silent, and holds your mic closed until the greeting audio lands so you don't talk over it. If the agent still doesn't greet first, say something or type in chat — it will respond. If it happens on every call with every agent, let the team know: it's the bug we're chasing hardest.

Mic blocked or missing

Check Settings → mic default, and your browser's site permissions. Either way, calls fall back to chat mode automatically — you type, the agent answers by voice.

Key issues

  • "No key entered" — the app can't start a call without a key; paste one in Settings.
  • "Key changed" — memories and history are key-scoped, so switching keys shows a fresh slate. Your old data is untouched, tied to the old key.
  • Quota errors — the key's Gemini quota is exhausted; wait for it to reset or use another key profile.

Other hiccups

  • Choppy audio — on a hosted tunnel the voice path can degrade; on the deployed server it should be clean. Check your connection first.
  • "Search unavailable" — the agent's web search runs a 4-provider chain (DuckDuckGo instant → Wikipedia → Google News → DDG web). If all four are blocked, it says so rather than inventing answers. Try again later.
  • Recording missing/empty — the mic was likely denied; allow it and call again.
  • Double greeting after transfer — report it; transfers should hand you over with a single greeting.

FAQ

Is this a real phone network? Can I call real numbers?
No. The +1 (555) numbers are fictional and work only inside the app. This is a demo, not a phone company, emergency service, or medical/legal/financial provider.
Where does my API key go?
Into server memory for the call only. Never stored, never logged, never in a URL. Data is keyed to your key by hash, so only you see your history.
Can I use it without a microphone?
Yes — chat mode. Type your messages; the agent still answers by voice.
Are my calls recorded?
On your device, for you. Recordings and transcripts never leave your device except into your own memory/backup — which is also yours.
Can I make my own agents?
Yes — the Custom Agents page (name, number, role, tone, voice, prompt, avatar), unlimited, saved per key. SymAgent even knows about them and can transfer callers to them.
Does my data survive redeploys?
Yes, if you did the DATA_DIR=/data volume step. Otherwise redeploys wipe it — keep a JSON backup from the Memory page.
Why does SymAgent ask for my details instead of answering a question?
That's its job: it's the company rep. It informs and captures leads (name, email, phone, service) for the team to follow up.
Why won't it discuss pricing?
By design — SymAgent doesn't talk pricing or book appointments. It connects interested callers with the team instead.
